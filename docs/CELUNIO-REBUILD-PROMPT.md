# Build "Celunio" — an AI photo studio with 23 tools (full rebuild spec)

Build a production-ready web application: an AI photo studio where a user picks one of 23 narrow tools (headshot, photo restoration, product shot, interior redesign, voiceover, etc.), uploads a photo or types a short brief, pays per run with prepaid credits, watches the result develop live, and gets a downloadable file plus a public share link. No subscriptions. English UI.

The defining architectural idea: **every tool is a declarative configuration object in a single registry, executed by one shared engine** — one run pipeline, one workspace UI renderer, one pricing mechanism. Adding a tool means adding a config object, not building a page.

---

## 1. Tech stack (fixed, do not substitute)

- **Next.js 15+ (App Router, TypeScript, Turbopack)**, deployed on **Vercel**
- **Tailwind CSS** for all styling; **shadcn/ui + Radix** for primitives (selects, switches, toasts, dialogs)
- **Neon Postgres** (serverless driver `@neondatabase/serverless`) with **Drizzle ORM**
- **Clerk** for authentication (email/password + Google OAuth), `@clerk/nextjs`
- **Vercel Blob** for generated files storage
- **OpenAI APIs** for all generation: `gpt-image-1` (images, incl. edits with input image and mask), GPT-4o/mini (text tools), `gpt-4o-mini-tts` (voiceover; voices Coral, Alloy, Verse, Sage, Ballad), `gpt-4o-transcribe`/Whisper (transcription)
- Fonts: **Geist** (sans) + **Geist Mono** via `next/font`
- Payments: **NOT in this phase.** Build the checkout UI and purchase data model, but behind a "card payments are being switched on" notice (see §10)

Env vars: `DATABASE_URL`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `CLERK_WEBHOOK_SIGNING_SECRET`, `OPENAI_API_KEY`, `BLOB_READ_WRITE_TOKEN`.

## 4. Credits economy (core rules)

- New account → **20 welcome credits**, recorded in the ledger as "Welcome bonus".
- Every run button shows its price: "Create · 2 cr", "Create 4 frames · 8 cr". Under the button, live hint: "Balance after this run: N"; if fields are missing, hint names the field ("Fill in 'What to draw'", "Pick a look", "Upload: your photo"). Insufficient balance → button leads to top-up.
- Credits are **debited when the run starts**. Technical failure (model error, timeout, refusal) → **automatic refund**, visible in the ledger. A disliked-but-finished result is not refunded.
- **Cache rule:** a rerun with byte-identical inputs is free — return the cached result (hash inputs per user+tool).
- Credits never expire; no subscription.
- Packs: **Starter** $9 = 100 cr ($0.090/cr, "About 50 studio frames"); **Creator** $19 = 350 + 50 bonus ($0.054/cr, "Best value", "Most picked — 50 credits on the house"); **Studio** $49 = 1,250 + 250 bonus ($0.039/cr); **Agency** $99 = 3,250 + 750 bonus ($0.030/cr). Pack card bullets: "N single images or M studio batches", "All 23 tools, no feature gates", "Credits never expire, failed runs refunded".

- Left column card = the form: file dropzone(s) ("Choose a file or drop it here", subtext with requirement, "up to 12 MB"; after upload shows thumbnail + filename + size + "× remove"), then controls in config order (select / text / textarea / switch / brush-mask canvas / look-picker), then the price button, then the hint line.

## 8. Database schema (Neon Postgres, Drizzle)

```
users            id (pk, = Clerk user id), email unique, name, created_at
credit_ledger    id, user_id fk, kind ('welcome'|'purchase'|'generation'|'refund'|'admin'),
                 delta int, balance_after int, ref text (run id / pack / note), created_at
runs             id (short slug, ~10 chars, nanoid), user_id fk, tool_slug, look_slug null,
                 params jsonb, cost int, status ('running'|'done'|'failed'|'cancelled'),
                 output_kind, text_output text null, input_hash text, created_at, finished_at
run_files        id, run_id fk, index int, filename ('out-0.png'…), blob_url, width, height, bytes
inspiration_posts id, run_id fk unique, user_id fk, title (look/tool name), tool_slug,
                 author_handle, likes int default 0, published_at
purchases        id, user_id fk, pack ('starter'|'creator'|'studio'|'agency'), price_cents,
                 credits int, status ('pending'|'paid'|'refunded'), billing jsonb, created_at
```

Balance = ledger sum (store `balance_after` for display). Debit at run start inside a transaction; refund row on failure. `input_hash` (sha256 of files+params+tool) powers the free-cache rule: same hash & user & done → return existing run, charge nothing.

## 13. Acceptance checklist

1. Sign up with Google (Clerk) → land on `/dashboard` with 20 credits and a "Welcome bonus" ledger row.
2. Free Generation: type ≤100 chars, pick format/style → "Working… Ns" timer → image streams in ≤60 s → Download works, `/r/[id]` opens signed-out, balance −2, ledger row added, gallery shows the tile.
3. Photo Studio: upload portrait → pick look → 4 frames develop one by one (~90 s) → balance −8 → "Share to Inspiration" → tile appears on public `/inspiration`.

5. Rerun identical inputs → instant cached result, no charge.
6. All 23 workspace forms render from the registry alone; `/tool/[slug]` and look pages generated from the same data (SSG).
7. Checkout stores a pending purchase and shows the "payments coming soon" notice.
8. Lighthouse: dark theme consistent, images lazy, public pages SSR/SSG with proper `<title>` ("{Tool} — {tagline} · Celunio") and OG tags.
